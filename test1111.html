node-fetch security crawl test page

Host this page and POST its URL to your crawler. Each section embeds attack vectors as real <img> tags. If your patches are working, none of these images should be fetched/stored. Check your server logs — any successful fetch is a gap.

1. scheme bypass

data: URI — 1x1 transparent PNG inline
data: URI — SVG (XSS risk even as image)
http: downgrade (not https)
protocol-relative URL (crawlers sometimes expand these)
file: scheme — local filesystem read attempt

2. SSRF — private IP ranges

loopback — 127.0.0.1
loopback — localhost hostname
RFC1918 — 10.x.x.x
RFC1918 — 172.16.x.x
RFC1918 — 192.168.x.x
AWS instance metadata endpoint
IPv6 loopback — [::1]
0.0.0.0 — wildcard address

3. URL obfuscation

decimal IP — 2130706433 resolves to 127.0.0.1
hex IP — 0x7f000001 resolves to 127.0.0.1
@ trick — parser sees evil.com, actual host is 127.0.0.1
credentials embedded in URL
URL-encoded dot — 127%2E0%2E0%2E1

4. redirect exploitation

open redirect → http:// downgrade
open redirect → 127.0.0.1 (SSRF via redirect)
open redirect → data: URI
redirect chain exceeding 20 hops (max-redirect)

5. response size / DoS

50 MB random bytes
infinite stream
no Content-Length header (streaming body)

6. timeout / slow response

60 second server delay
drip — 1 byte per second for 120 seconds

7. content-type spoofing

HTML body served with Content-Type: image/png
SVG with script — served as image/svg+xml
no Content-Type header at all
